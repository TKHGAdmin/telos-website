## BUG-2026-09-23-001 — Product detail page layout broken when a product has multiple images

**Severity:** P1
**Category:** Functional / Layout regression
**Introduced:** commit `f5cb8c4` — "feat: add image gallery with thumbnails on product page"
**File:** `product.html:765-780` (DOM), `product.html:100-108` (CSS)

### What's wrong

`.product-detail.loaded` is a 2-column CSS grid:

```css
.product-detail.loaded {
  display: grid;
  grid-template-columns: 1fr 1fr;
}
```

But `#productDetail` has **three direct children**, not two — the thumbnail rail was inserted as a sibling of image and info rather than nested with the image:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-image" id="productImage"></div>
  <div class="product-detail-thumbs" id="productThumbs"></div>   <!-- 3rd grid cell -->
  <div class="product-detail-info">
    <span id="productType"></span>
    <h1 id="productTitle"></h1>
    <div id="productPrice"></div>
    <button id="productAddBtn">Add to Cart</button>
    ...
  </div>
</div>
```

With auto-placement, the three children land as:

| Row | Col 1 | Col 2 |
|---|---|---|
| 1 | image | **thumbs** |
| 2 | **info (title, price, add-to-cart, description)** | (empty) |

Instead of the intended:

| Row | Col 1 | Col 2 |
|---|---|---|
| 1 | image + thumbs stacked | info |

### Repro

1. In Shopify admin, add any product with 2+ images.
2. Open `https://www.telosathleticclub.com/product?p=<handle>` on desktop (≥769px).
3. Observe: the image sits in the top-left, an orphan thumbnail strip sits to its right, and the entire product info block (title, price, Add to Cart button, description) is pushed to a second row underneath the image with a large empty gutter on the right.

### Expected vs actual

- **Expected:** Two-column layout — image (with thumbs under it) on the left, product info on the right, matching the pre-thumbnail layout.
- **Actual:** Three-cell layout that displaces the entire info column. Add-to-Cart button falls below the fold on many viewports; page looks unfinished.

### Note on mobile

Mobile view (`max-width: 768px`) collapses to a single column, so the stacking is image → thumbs → info, which is coincidentally the correct order there. The bug is desktop-only.

### Suggested fix

Wrap the image and thumbs in a shared container so the grid sees only two children:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-media">
    <div class="product-detail-image" id="productImage"></div>
    <div class="product-detail-thumbs" id="productThumbs"></div>
  </div>
  <div class="product-detail-info">...</div>
</div>
```

Alternative (CSS-only): `.product-detail-info { grid-column: 2; grid-row: 1 / span 2; }` and `.product-detail-thumbs { grid-column: 1; }` — less clean, more fragile.

## BUG-2026-09-23-002 — shop.html serves stale `js/shop.js` to returning visitors (clickable cards broken)

**Severity:** P2
**Category:** Cache invalidation
**Files:** `shop.html:841`, `product.html:822`

### What's wrong

`js/shop.js` was updated across multiple recent commits (adds `loadProductDetail`, `addToCartFromDetail`, `switchProductImage`, and — critically for shop.html — the `card.addEventListener('click', ...)` in `createProductCard` that makes product cards navigate to `product?p=…`).

Cache-bust query strings drifted:

- `shop.html:841` → `<script src="js/shop.js?v=1"></script>`
- `product.html:822` → `<script src="js/shop.js?v=2"></script>`

The project convention (per `CLAUDE.md`: "CSS cache busting: Stylesheet references use `?v=N` query param. Bump the version on all pages when changing style.css.") extends to JS in practice. Because shop.html was never bumped, returning visitors whose browser cached `js/shop.js?v=1` from before the update will keep serving the pre-`21cc926` version — meaning **product cards on /shop won't be clickable** for those users until they hard-refresh.

### Repro

1. Visit `/shop` before the `21cc926` deploy. Browser caches `js/shop.js?v=1`.
2. Post-deploy, revisit `/shop` on the same browser.
3. Click a product card body (not the Add to Cart button).
4. **Expected:** navigate to `/product?p=<handle>`.
5. **Actual:** nothing happens — the click handler was added in the updated shop.js, which the browser doesn't refetch because the URL is unchanged.

New/private-mode visitors won't hit this because they fetch fresh; only returning visitors are affected.

### Suggested fix

Bump `shop.html:841` to `js/shop.js?v=2` (or higher) to match `product.html`, and adopt a convention: bump on every shop.js edit, on **both** pages that load it. Same discipline applies to `js/main.js?v=2` if it ever changes.

## Not-a-bug notes (for the record — checked and cleared)

- **`SHOPIFY_STOREFRONT_TOKEN` hardcoded in `js/shop.js:15`.** Shopify's Storefront Access Tokens are intentionally public; they're rate-limited and scoped by the shop to read-only storefront queries. Not a leaked secret.
- **`descEl.innerHTML = product.descriptionHtml` at `js/shop.js:199`.** Content comes from Shopify admin (single trusted author). Standard Shopify integration pattern. Not an XSS vector under current authoring model.
- **Variant/line-item IDs interpolated into `onclick` attributes.** Shopify IDs are opaque base64 GIDs with no `'`, `"`, or `\` characters. No injection surface in practice, though moving to `addEventListener` would be cleaner long-term (style, not bug).
- **CLAUDE.md doesn't yet document `shop.html` / `product.html` or the shop integration.** Documentation gap, not a functional bug — flagging here so it can be picked up whenever the doc is next touched.
