## BUG-2026-07-02-01 — Product detail page: thumbnail gallery breaks 2-column desktop layout

- **Severity:** P1
- **Focus:** Functional (layout)
- **Files:**
  - `product.html:106-108` (grid definition)
  - `product.html:765-780` (DOM structure — three grid children)
  - `js/shop.js:161-177` (JS that populates the thumb container)
  - Introduced by commit `f5cb8c4` — "feat: add image gallery with thumbnails on product page"
- **Affected surface:** Every product detail page (`/product?p=<handle>`), desktop viewport (>768 px). Mobile is unaffected — the `@media (max-width: 768px)` rule collapses the grid to a single column, which happens to place the thumbs correctly under the image.

### What's broken

`.product-detail.loaded` is a two-column CSS grid:

```css
.product-detail.loaded {
  display: grid;
  grid-template-columns: 1fr 1fr;
}
```

The original DOM had exactly two direct children: `#productImage` (left column) and `.product-detail-info` (right column). The May-20 gallery commit added a **third** direct child, `#productThumbs`, between them:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-image"  id="productImage"></div>
  <div class="product-detail-thumbs" id="productThumbs"></div>   <!-- new -->
  <div class="product-detail-info">…</div>
</div>
```

With three items in a two-column grid the auto-placement algorithm produces:

| | Col 1 | Col 2 |
|---|---|---|
| **Row 1** | main image | **thumbnails** (should be under the image) |
| **Row 2** | product info (title / price / add-to-cart / description) | *empty* |

Effects on desktop:

1. **Thumbnails render beside the main image instead of below it** — the `margin-top: 12px` in `.product-detail-thumbs` no longer positions them under the hero image, because they're in a different column.
2. **The info panel is squeezed to half viewport width** and leaves a large empty gutter to its right, so the "Add to Cart" button and description look orphaned.
3. This happens for **every product**, even ones with a single image — `js/shop.js:168` only writes into `#productThumbs` when there are 2+ images, but the empty `<div>` is still a grid item and still occupies row-1 col-2.

### Repro

1. Open `https://www.telosathleticclub.com/product?p=<any-handle>` on desktop (>768 px viewport).
2. Observe: main image on the left, thumb strip (or empty box, if single image) on the right, title/price/add-to-cart pushed to a second row occupying only the left half.
3. Expected: main image + thumbs strip on the left half; title/price/add-to-cart/description on the right half, as before commit `f5cb8c4`.

### Suggested fix

Either wrap the image + thumbs into a shared grid child, e.g.

```html
<div class="product-detail-gallery">
  <div class="product-detail-image"  id="productImage"></div>
  <div class="product-detail-thumbs" id="productThumbs"></div>
</div>
<div class="product-detail-info">…</div>
```

…or change the grid to `grid-template-columns: 1fr 1fr; grid-template-areas: "img info" "thumbs info";` and assign `grid-area` to each child so the info panel spans both rows. The wrapper approach is smaller and matches how the mobile media query already reads.

### Why P1 (not P0 or P2)

- Product pages are a live commercial surface — anything driving cart adds sits behind this layout.
- No JS or checkout functionality is broken; the Add-to-Cart button still works. So it degrades experience rather than blocking purchase → not P0.
- Affects all desktop users viewing any product → too broad for P2 ("some users / edge cases").
