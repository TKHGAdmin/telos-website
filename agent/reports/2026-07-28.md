### BUG-20260728-01 - Two tool pages ship a different top-nav than the rest of the site [P2]

### BUG-20260728-02 - Calculator pages don't load `js/main.js`, so button ripples / magnetic hover / nav glassmorphism are silently absent [P2]

- **File(s):** `hyrox-predictor.html` (no `<script src="js/main.js">`), `protein-calculator.html` (same). `js/main.js:14-25, 255-312`.
- **First seen:** 2026-07-28 (already acknowledged in `CLAUDE.md` "Known Limitations")
- **Recurring?:** yes, referenced in `CLAUDE.md` "Bug crawl P1-P3 backlog"; still unresolved.

**What's wrong**
`js/main.js` powers 14 shared behaviors: nav "scrolled" glassmorphism class on scroll (`main.js:14-25`), `.btn` click ripple (`main.js:289-312`), `.btn-primary`/`.btn-outline` magnetic hover (`main.js:255-271`), cursor glow (`main.js:138-166`), hero parallax, section-label reveal, dropdown toggles, etc. Grep confirms the two calculator pages don't include the script. Their own inline scripts cover only the hamburger toggle - everything else silently no-ops. Result: the Book-a-Call and Calculate buttons on these pages behave visibly differently from the same buttons on every other page.

Neither calculator uses `.animate-on-scroll` or `.card-tilt`, so those specific misses are inert - the report intentionally scopes the impact to behaviors that WOULD fire if `main.js` were loaded.

**Repro / evidence**
```
$ grep -l 'js/main\.js' *.html
chs.html
index.html
pricing.html
product.html
resources.html
shop.html
# note: hyrox-predictor.html and protein-calculator.html are absent
```

Load `/hyrox-predictor` in Chrome desktop → hover the gold "Predict My Time" button → no magnetic pull, no ripple on click. Load `/pricing` → hover any gold button → magnetic pull, ripple on click.

**Suggested fix**
Add `<script src="js/main.js"></script>` before the closing `</body>` on both pages. Then delete the duplicate inline hamburger handler at `protein-calculator.html:785-790` and `hyrox-predictor.html:~same` since `main.js` already binds it (per `CLAUDE.md`: "tool pages ... must NOT duplicate hamburger/nav handlers").

### BUG-20260728-03 - `.html` extensions in internal nav links trigger a 308 redirect on every click [P3]

- **File(s):** `protein-calculator.html:482, 484-488, 504-508, 728`; `hyrox-predictor.html:481, 483, 500`; all 23 files under `blog/` (representative: `blog/former-athlete-identity.html:271-501`, `blog/intermittent-fasting-athletes.html:375-620`).
- **First seen:** 2026-07-28 (already acknowledged in `CLAUDE.md` "Known Limitations")
- **Recurring?:** yes, referenced in `CLAUDE.md` "Bug crawl P1-P3 backlog"; still unresolved.

**What's wrong**
`vercel.json` sets `cleanUrls: true`, which means any request to `/index.html` returns a 308 redirect to `/`. Every internal link in the tool pages and every blog article still hard-codes `href="index.html"` (and `../index.html#faq`, etc.). Users clicking those links pay one extra HTTP round-trip per navigation; search engines see the redirect chain as a signal against the destination. `CLAUDE.md` explicitly says "All internal links use clean URLs without `.html` extension" so this is a codified convention that ~25 files are silently violating.

**Repro / evidence**
```
$ grep -rn 'href="[^"]*\.html' *.html blog/*.html | grep -v "http" | wc -l
# ~120+ hits across the two calculators and the 23 blog files
```
Spot check:
- `protein-calculator.html:484` → `href="index.html#how-it-works"`
- `hyrox-predictor.html:483` → `href="index.html"` (should be `href="/"` or just `"index"` if you want to keep it relative-safe)
- `blog/former-athlete-identity.html:271` → `href="../index.html"` (should be `../`)

Curl one:
```
$ curl -sI https://www.telosathleticclub.com/index.html
HTTP/2 308
location: /
```

**Suggested fix**
One-time codemod: `sed -i 's/href="index\.html/href="\//g; s|href="\.\./index\.html|href="../|g' *.html blog/*.html`. Then spot-audit for edge cases where the anchor becomes weird (e.g. `href="index.html#faq"` → `href="/#faq"`). Bump `?v=17` on style.css during the same commit so any cached copies of the old blog pages get a matching refresh.
