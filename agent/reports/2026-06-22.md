## [P1] Product detail page renders broken 2-column grid (image + thumbs + info)

**ID:** 2026-06-22-1
**Surface:** product.html, js/shop.js
**Lines:** product.html:100-115, product.html:765-780, js/shop.js:161-177
**Status:** new

### What's wrong
The product detail page uses `display: grid; grid-template-columns: 1fr 1fr` on `.product-detail.loaded` but the container has THREE direct children: `#productImage`, `#productThumbs`, and `.product-detail-info`. With three children in a two-column grid, the browser lays them out as image (top-left) / thumbs (top-right) / info (bottom-left, half width), leaving the bottom-right cell empty. The intended design is image+thumbs stacked in the left column, info in the right column. The bug was introduced by the recent gallery feature (commit `f5cb8c4`) which added `#productThumbs` as a sibling of `#productImage` rather than nesting it.

### Why it matters
On desktop (>768px), every visitor to a product page sees:
- a half-width product image in the top-left,
- thumbnails (or an empty cell) in the top-right where the title/price/CTA should be,
- the title, price, Add-to-Cart button, and description pushed below the image at half width.

The Add to Cart button is well below the fold next to empty space - it kills conversion on the only path that earns revenue from the shop. On mobile the media query collapses to one column, so this only shows on desktop / tablet landscape (where the recent commits were probably not tested).

### Repro
1. Deploy current main (commit `f5cb8c4`) or open product.html locally.
2. Add at least one product in Shopify with two or more images.
3. Visit `/shop`, click any product card -> lands on `/product?p=<handle>`.
4. On a desktop viewport (>768px), observe the layout: image + thumbs occupy row 1, title/price/CTA occupy row 2 col 1, row 2 col 2 is empty.

### Suggested fix
Wrap the image and thumbs in a single column container so the grid sees only two children:

```html
<!-- product.html lines 765-780 -->
<div class="product-detail" id="productDetail">
  <div class="product-detail-media">
    <div class="product-detail-image" id="productImage"></div>
    <div class="product-detail-thumbs" id="productThumbs"></div>
  </div>
  <div class="product-detail-info">
    <!-- unchanged -->
  </div>
</div>
```

No JS changes needed - `getElementById('productImage')` and `getElementById('productThumbs')` still resolve. Add a one-line CSS rule if needed:

```css
.product-detail-media { display: flex; flex-direction: column; }
```

Alternative one-line CSS-only fix (no HTML change): set `grid-column: 1` on `#productThumbs` and `grid-row: 1 / span 2` on `#productImage` -- but the wrapper approach is cleaner.

## [P2] shop.js cache-busting drift: shop.html stuck on v=1, product.html on v=2

**ID:** 2026-06-22-2
**Surface:** shop.html, product.html
**Lines:** shop.html:841, product.html:822
**Status:** new

### What's wrong
The two consumers of `js/shop.js` ship different cache-busting query strings:
- `shop.html:841` -> `<script src="js/shop.js?v=1"></script>`
- `product.html:822` -> `<script src="js/shop.js?v=2"></script>`

Every other shared-asset bump in this repo is kept in sync across consumers (e.g. all 33 references to `style.css?v=16`, all 28 references to `main.js?v=2`). When `shop.js` was bumped to `v=2` (presumably with the gallery fix on product.html), `shop.html` was missed.

### Why it matters
Returning visitors to `/shop` who already have `shop.js?v=1` cached in their browser will continue to run the old shop logic indefinitely (the URL hasn't changed). Any bug fix or feature added to `shop.js` after the bump is invisible to them on the shop landing page, even though it works on `/product`. Cache-busting only protects against this when every page advances the version together.

### Repro
```
grep -n 'shop.js?v=' shop.html product.html
shop.html:841:  <script src="js/shop.js?v=1"></script>
product.html:822:  <script src="js/shop.js?v=2"></script>
```

### Suggested fix
Update `shop.html:841` to match:
```html
<script src="js/shop.js?v=2"></script>
```

Going forward, treat `shop.js?v=N` like `style.css?v=N` and `main.js?v=N` - bump every reference together. Worth adding to CLAUDE.md under "Important Conventions" if not already.
