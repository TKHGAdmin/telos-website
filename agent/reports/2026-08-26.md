## Bug 1 — Product detail page: thumbnail strip breaks two-column layout

- **ID**: `2026-08-26-1`
- **Severity**: P1
- **Area**: `/product` (product detail page)
- **File**: `product.html:766-767` (DOM), `product.html:105-108` (CSS)
- **Category**: functional

**Summary**

The `.product-detail` container is a two-column CSS grid (`grid-template-columns: 1fr 1fr`) but has **three** direct children: `#productImage`, `#productThumbs`, `#productDetail-info`. Grid auto-placement puts the thumbnails strip in row 1 / column 2 — the slot meant for the product info — and pushes the product info (title, price, add-to-cart button, description) down to row 2. On desktop, every product page currently renders with the buy panel below the image instead of beside it, and an empty grid cell to its right. Introduced in commit `f5cb8c4` ("feat: add image gallery with thumbnails on product page").

**Reproduction / evidence**

`product.html` lines 764-780:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-image" id="productImage"></div>
  <div class="product-detail-thumbs" id="productThumbs"></div>
  <div class="product-detail-info">
    <span class="product-detail-type" id="productType"></span>
    ...
  </div>
</div>
```

`product.html` lines 105-108:

```css
.product-detail.loaded {
  display: grid;
  grid-template-columns: 1fr 1fr;
}
```

Three grid items into two columns → the third item wraps to row 2. The bug fires even for single-image products because `#productThumbs` is present in the DOM regardless of image count (it is just left empty). Verified by tracing the commit diff — before `f5cb8c4` the container had exactly two children (image and info) and the layout worked.

**Suggested fix**

Move `#productThumbs` inside a wrapper that also holds the image, so the grid still sees two columns:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-media">
    <div class="product-detail-image" id="productImage"></div>
    <div class="product-detail-thumbs" id="productThumbs"></div>
  </div>
  <div class="product-detail-info"> ... </div>
</div>
```

No CSS changes are needed — `.product-detail-thumbs` already has `margin-top: 12px`, which will now sit under the image as intended.

## Bug 2 — `js/shop.js` cache-busting version mismatch between shop.html and product.html

- **ID**: `2026-08-26-2`
- **Severity**: P2
- **Area**: `/shop` and `/product`
- **File**: `shop.html:841`, `product.html:822`
- **Category**: functional

**Summary**

`shop.html` and `product.html` load the same file, `js/shop.js`, with different cache-busting query strings — `?v=1` on `shop.html` and `?v=2` on `product.html`. The two URLs are treated as separate cache entries by every browser. Returning visitors who saw `shop.html` before the shop was updated will keep serving the stale `?v=1` copy indefinitely, and any future bump to only one page will silently leave the other stale. This is the same class of bug CLAUDE.md's "CSS cache busting" convention exists to prevent.

**Reproduction / evidence**

```
$ grep -n 'shop\.js\?v=' shop.html product.html
shop.html:841:  <script src="js/shop.js?v=1"></script>
product.html:822:  <script src="js/shop.js?v=2"></script>
```

Any user who visited `shop.html` on the initial deploy and returns after `js/shop.js` is edited will re-use the browser-cached `?v=1` copy. The version was only bumped on `product.html` in the recent gallery commit (`f5cb8c4`), leaving `shop.html` behind. Concretely, the `switchProductImage` function and the two-image gallery logic are already available on `product.html` but a stale `shop.html` visitor could still hit an older `addToCart` or `createProductCard` implementation.

**Suggested fix**

Bump `shop.html:841` to `js/shop.js?v=2` to match `product.html`. Longer-term, add a note to CLAUDE.md's "Important Conventions" section that `js/shop.js` version must be bumped on **both** `shop.html` and `product.html` whenever it changes (same convention as `?v=16` on `style.css`).
