## Bug 2026-10-28-01

**Severity:** P2
**File:** api/cron/weekly-summary.js:86-90
**Summary:** The weekly recap email always reports "Current Streak: 0 days" for every client, because the cron fires Monday morning before anyone has logged for Monday and the streak loop breaks on the first missing day.

### Reproduction

The cron is scheduled Monday 14:00 UTC (`vercel.json` line 21) — that is 09:00 ET during standard time, 10:00 EDT during DST.

For each active client the handler builds a 7-slot window where `d=0` is today (`api/cron/weekly-summary.js:46-47`):

```js
for (var d = 0; d < 7; d++) {
  var dateStr = new Date(now - d * 86400000).toISOString().split('T')[0];
  logCmds.push(['GET', 'client_dailylog:' + client.id + ':' + dateStr]);
  ...
}
```

Then it computes the streak (`api/cron/weekly-summary.js:86-90`):

```js
// Count streak (from today backwards)
for (var d = 0; d < 7; d++) {
  if (weekData[0][d] && weekData[0][d].result) streak++;
  else break;
}
```

At 09–10 ET on a Monday, the only clients whose `d=0` slot (today's Monday log) is populated are the handful who opened the dashboard and submitted the daily check-in in the first few hours of the day. For every other active client, `weekData[0][0].result` is falsy, the loop breaks on the first iteration, and `streak` stays `0`.

That `0` is then interpolated into the email at `api/cron/weekly-summary.js:131`:

```
Current Streak: <strong style="color:#C9A84C;">0 days</strong>
```

So a client who logged every single one of the previous seven days still sees "Current Streak: 0 days" in Monday's recap.

### Impact

- Every active client with `portalEnabled && emailEnabled !== false` receives a weekly email that under-reports (almost always to zero) the one metric most likely to drive retention.
- The streak counter is prominent in the email body — it is one of four stat lines and the second from the top.
- The bug has existed since the cron was written; `git log --oneline -20` shows no touch to this file. It will fire again next Monday.

### Suggested fix

Define "current streak" to end at yesterday, not today — today has not finished yet so an unlogged `d=0` is not a break. Replace the loop with:

```js
// Count streak ending yesterday (today may not be logged yet when the cron fires)
for (var d = 1; d < 7; d++) {
  if (weekData[0][d] && weekData[0][d].result) streak++;
  else break;
}
// If today is already logged, add it on top.
if (weekData[0][0] && weekData[0][0].result) streak++;
```

Keep the `d < 7` ceiling as it is — the window only pulls seven days, so seven is the maximum streak this cron can observe either way. A longer true streak is a separate feature (would require reading `client_dailylogs_index` via `ZREVRANGEBYSCORE`), not required to fix this bug.
