## Summary

First run of the Telos Bug Hunter. Focus: functional. Concentrated on the newly shipped `/shop` and `/product` pages (the last eight commits are all shop work, and the most recent one — `f5cb8c4 feat: add image gallery with thumbnails on product page` — is the freshest change on the codebase). Two real bugs turned up: (1) a layout regression introduced by that gallery commit that visibly breaks every product-detail page on desktop, and (2) an error-handling gap on `product.html` where a Shopify init failure leaves users staring at a spinner forever. Both are reproducible from the code alone, both are recent, and both are on the current happy path for a customer trying to buy something.

## Findings

### [P1] Product-detail grid puts thumbnails where price and copy should be (product-detail-grid-3-children)

- **Severity:** P1
- **Area:** shop
- **File(s):** `product.html:101-108` (CSS `.product-detail.loaded`), `product.html:765-780` (HTML structure)
- **Reproduction:**
  1. Deploy or open `product.html` locally.
  2. Visit `/product?p=<handle>` for any Shopify product that has at least one image, on a viewport wider than 768px.
  3. Wait for the SDK to load and `productDetail` to gain the `loaded` class.
- **Failure:** The product image renders correctly in the left column, but the thumbnail strip (`#productThumbs`) lands in the right column of row 1 — the slot the price, title, "Add to Cart" button, and description were supposed to occupy. `.product-detail-info` gets pushed to row 2, column 1, leaving the entire right side of row 2 blank. Result: on every desktop product view, the page looks broken and the buy button appears far below the fold.
- **Root cause:** `commit f5cb8c4` added a third direct child (`<div class="product-detail-thumbs" id="productThumbs"></div>`) into `#productDetail` at `product.html:767`, but the grid template at `product.html:106-108` is still `grid-template-columns: 1fr 1fr`. Three items in a two-column, row-major grid → image, thumbs, info fill cells (1,1), (1,2), (2,1) in that order; the info panel wraps to a new row because there's no room for it beside the thumbs. The mobile media query at `product.html:110-115` collapses to `1fr` so the bug is masked below 768px.
- **Suggested fix:** Wrap the image and thumbs in a single `.product-detail-media` div so the grid sees only two children again, or add `.product-detail-image, .product-detail-thumbs { grid-column: 1; }` and `.product-detail-info { grid-column: 2; grid-row: 1 / span 2; }` so the info panel occupies the full right column. The first approach matches the CSS's original intent (`margin-top: 12px` on the thumbs strip clearly expected it to sit beneath the image).
- **Confidence:** high

### [P1] Product page shows an infinite spinner when Shopify init fails (product-init-error-silent)

- **Severity:** P1
- **Area:** shop
- **File(s):** `js/shop.js:24-35`, `js/shop.js:69-73`, `js/shop.js:502-507`
- **Reproduction:**
  1. Load `/product?p=<handle>` under any condition that makes the outer init throw before `loadProductDetail()` runs. Concrete cases:
     - Block or interrupt `https://sdks.shopifycdn.com/js-buy-sdk/...` in DevTools (or the Shopify CDN is down / ad-blocked).
     - Rotate/invalidate the storefront token so `shopifyClient.checkout.create()` rejects.
     - Any transient 5xx from Shopify during `checkout.fetch`/`create` at page load.
  2. Watch the page.
- **Failure:** The loading spinner (`#productLoading`, visible by default) never disappears. `#productNotFound` and `#productDetail` both remain `display: none`. No error text, no retry button, no "Back to Shop" fallback — the user is stranded. The customer has no idea whether the site is broken, the product is missing, or their connection is flaky.
- **Root cause:** The init routine handles product-page errors only inside `loadProductDetail()`'s own try/catch (`shop.js:216-220`). Every earlier failure path — SDK missing (`shop.js:24-28`), config still stubbed (`shop.js:31-35`), any throw inside the outer `try` at `shop.js:37-72` — calls `showEmpty()`. `showEmpty()` at `shop.js:502-507` only knows about `#shopLoading` and `#shopEmpty`, which exist on `shop.html` but NOT on `product.html`. On the product page, `showEmpty()` is a silent no-op and nothing hides the spinner.
- **Suggested fix:** Teach `showEmpty()` to also hide `#productLoading` and reveal `#productNotFound` when those elements are present, or add a dedicated `showProductError(msg)` that the four early-failure branches call when they detect the product page. Either way, the spinner should never be the terminal state on an unhandled error.
- **Confidence:** high

## Notes

- The Shopify Storefront token committed in `js/shop.js:15` is intentional — Storefront API tokens are public credentials meant to ship in client code. Recorded in `learnings.md` so future security-focus runs don't re-flag it.
- The two `<script src="js/shop.js?v=N">` references use `?v=1` on `shop.html` and `?v=2` on `product.html`. Same file, drifting cache buster — minor cache waste, not a defect worth reporting on its own.
