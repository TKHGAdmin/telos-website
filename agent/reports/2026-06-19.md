## Findings

### BUG-20260619-1 - Product detail page layout broken on desktop

- **Severity**: P1
- **Area**: shop/product
- **File(s)**: `product.html:765-779`, `product.html:99-115`
- **Status**: new

**What's wrong**

`.product-detail.loaded` is declared as `display: grid; grid-template-columns: 1fr 1fr` (2 columns) but has 3 direct children in the DOM: `#productImage`, `#productThumbs`, `#productDetail-info`. CSS Grid auto-flow places them as `(image col1 row1)`, `(thumbs col2 row1)`, `(info col1 row2)`. The product info column drops below the image instead of sitting beside it, and an empty / thumbnail-only cell takes up the entire top-right quadrant.

This breaks for ALL products on viewports above 768px (the mobile media query at line 110 collapses the grid to `1fr` so it stacks correctly there). The recent fix commits (`a3b1e87`, `4b1bd3c` "move add-to-cart above description") were mobile-focused, which is likely why the desktop regression slipped through.

**Reproduction**

1. Open any product on the live site at a desktop width (>768px): e.g., `/product?p=<any-handle>`.
2. Observe: image is in the top-left half-width, info (title/price/add-to-cart/description) is rendered BELOW the image in the bottom-left, and the top-right is empty (or contains thumbnails floating with nothing under them).
3. Expected: image on the left half, info column on the right half, optional thumbnails stacked under the image inside the left column.

You can also verify mechanically: `product.html` declares `display: grid; grid-template-columns: 1fr 1fr` at line 106-108 and the parent `#productDetail` has three element children at lines 766-779.

**Impact**

Every desktop visitor who clicks into a product sees a broken layout. This is the primary conversion surface for the new Shop feature (Shopify integration just went live), so the bug actively suppresses sales.

**Suggested fix**

Wrap the image and thumbs in a single grid-item container so the grid only sees two children:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-gallery">
    <div class="product-detail-image" id="productImage"></div>
    <div class="product-detail-thumbs" id="productThumbs"></div>
  </div>
  <div class="product-detail-info">
    ...
  </div>
</div>
```

No new CSS class is strictly required - `.product-detail-gallery` can be unstyled or get `display: flex; flex-direction: column;` if you want explicit control. The existing `.product-detail-thumbs { margin-top: 12px }` will continue to work.

### BUG-20260619-2 - shop.js cache version drift between shop.html and product.html

- **Severity**: P3
- **Area**: shop/product
- **File(s)**: `shop.html:841`, `product.html:822`
- **Status**: new

**What's wrong**

`shop.html` loads `<script src="js/shop.js?v=1">` while `product.html` loads `<script src="js/shop.js?v=2">`. They share the same physical file but request it under different cache-busting query strings. A returning visitor who already cached `shop.js?v=1` (e.g., browsed the shop list before the gallery feature shipped) will continue serving the pre-gallery version on shop.html until either the file changes again or the version on shop.html bumps. The product page works because `?v=2` forces a fresh fetch on product.html.

Right now, `js/shop.js` is the version with `loadProductDetail()`, `switchProductImage()`, and the multi-image gallery code. The old cached version (`v=1`) does not include `switchProductImage` and a few related helpers - but those are only invoked from product.html, so shop.html itself still functions. The drift is currently invisible; the bug is that it will silently bite the next time a shop.js change matters for shop.html.

**Reproduction**

1. `grep -n 'shop.js?v=' shop.html product.html`
2. Output shows `?v=1` on shop.html and `?v=2` on product.html.

**Impact**

Returning visitors may run mismatched JS between the two pages. Today this is latent; the moment a shop.html-relevant bugfix lands in shop.js without bumping `shop.html`'s `?v=`, returning users get the stale version and the fix won't propagate.

**Suggested fix**

Bump `shop.html:841` from `?v=1` to `?v=2` (or whatever the current product.html version is), and pick one convention going forward: every shop.js change bumps the version on BOTH pages.

```
<!-- shop.html line 841 -->
<script src="js/shop.js?v=2"></script>
```
