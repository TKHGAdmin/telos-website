## Summary

First run of the bug hunter. Focus was functional correctness of recent shop/product changes (image gallery commit `f5cb8c4`). One confirmed P1 layout regression on `/product` desktop breaks the primary product page whenever a product has more than one image.

## Bug 1

**Severity:** P1
**Area:** product.html / js/shop.js (image gallery, commit f5cb8c4)
**Focus:** functional

### What is wrong

On the product detail page, three direct children (`.product-detail-image`, `.product-detail-thumbs`, `.product-detail-info`) sit inside a two-column grid (`.product-detail.loaded { grid-template-columns: 1fr 1fr }`). Auto-placement pushes the thumbnails strip into row 1 / column 2 and drops the entire product info block (title, price, add-to-cart button, "instant digital delivery" note, and description) into row 2 / column 1, well below the fold on desktop viewports. The visible desktop layout becomes: image on the left, an empty thumbnails strip on the right, and everything the customer needs to actually buy the product hidden underneath the image.

### Reproduction

1. Open `product.html` in the browser at viewport width >= 768px (mobile stacks to a single column and is unaffected).
2. Load any product that returns >= 2 images from the Shopify Storefront API (`shopifyClient.product.fetchByHandle(handle)`), so `js/shop.js:168` populates `#productThumbs`.
3. Observe:
   - `#productImage` renders at approx. `left=122, right=608` (left column).
   - `#productThumbs` renders at approx. `left=672, right=1158` (right column, where the buy panel should be).
   - `.product-detail-info` renders at `top=750, left=122` (row 2, left column, below the image).
4. Layout verified with Playwright at 1280x800 (see rects captured during hunt: image top=200 / thumbs top=212 / info top=750).

The regression was introduced by commit `f5cb8c4 feat: add image gallery with thumbnails on product page`, which added `<div class="product-detail-thumbs" id="productThumbs"></div>` as a sibling of `.product-detail-image` and `.product-detail-info` inside `#productDetail` (product.html:766-768) without updating the `grid-template-columns` rule at product.html:105-108.

### Impact

Every desktop visit to a multi-image product page. The title, price, "Add to Cart" CTA, and description are pushed below a 486px-tall image, so users landing on a product see only the image and an unlabeled thumb strip in the initial viewport. Conversion path for the paid Shop tab is directly degraded, and the empty right column makes the page look broken. Products with exactly one image are unaffected (shop.js:168 gates the thumbs population on `allImages.length > 1`), so the bug will not be visible during casual testing with single-image products.

### Suggested fix

Move the thumbnails out of the top-level grid: wrap `#productImage` and `#productThumbs` in a single left-column container (e.g. `.product-detail-media`) that becomes the first grid child, so the grid still sees two children in two columns and the thumbs stack below the image inside the left cell. Alternatively, set `grid-column: 1` on `#productImage` and `#productThumbs` and `grid-column: 2; grid-row: 1 / span 2` on `.product-detail-info`. Either fix leaves the mobile single-column media query untouched.

### Confidence

CONFIRMED (reproduced with Playwright at 1280x800 using injected DOM matching what `loadProductDetail` builds; bounding rects and screenshot in scratchpad confirm the info panel drops to row 2).
