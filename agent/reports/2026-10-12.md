## Findings

### [P1] Product detail gallery breaks desktop layout — image and info end up in wrong grid cells

- **File:** `product.html:100-115` (CSS), `product.html:765-780` (markup)
- **Introduced in:** `f5cb8c4` "feat: add image gallery with thumbnails on product page"
- **What's wrong:**
  The `.product-detail` container is `display: grid; grid-template-columns: 1fr 1fr;` with **three** direct children in this order:
  1. `#productImage` (big image)
  2. `#productThumbs` (thumbnail strip)
  3. `.product-detail-info` (title / price / add-to-cart / description)

  CSS Grid auto-flow places them left-to-right, so on desktop (>768px) you get:

  ```
  [ big image     ][ thumb strip   ]   <- row 1
  [ title/price   ][ (empty)       ]   <- row 2
  ```

  The intended layout for a product page is image + thumbs stacked on the left, info on the right. The thumbnails end up as a tiny 72px strip floating in the top-right of a half-width column, and the info card ends up under the image on the LEFT instead of beside it on the right. Every product with multiple images will render this way on desktop; every single-image product renders with an empty 525px-wide column to the right of the info.
- **Why it's a bug, not a style preference:** Mobile fallback at `max-width: 768px` collapses to `grid-template-columns: 1fr` and stacks everything in the correct order. That mobile stacking order (image, thumbs, info) is the authoritative statement of intent — desktop is just the broken one.
- **Suggested fix (not applied — read-only agent):** Either wrap `#productImage` + `#productThumbs` in a single left-column div, or add explicit grid placement:
  ```css
  .product-detail.loaded { grid-template-columns: 1fr 1fr; }
  #productImage, #productThumbs { grid-column: 1; }
  .product-detail-info { grid-column: 2; grid-row: 1 / span 2; }
  ```
- **Severity rationale:** P1 — degrades the newest, most visible page on every desktop visit. Not P0 because the Add-to-Cart button still works and mobile is fine.

### [P2] Thumbnail elements are divs with onclick, no keyboard access

- **File:** `js/shop.js:170` (generated markup for `.product-thumb`)
- **What's wrong:** Thumbnails are rendered as `<div class="product-thumb" onclick="switchProductImage(...)">`. They are not keyboard-focusable, have no `role="button"`, no `tabindex="0"`, and no `aria-label`. Keyboard-only users and screen-reader users cannot switch images in the gallery.
- **Suggested fix:** Render each thumb as `<button type="button" class="product-thumb" aria-label="Show image 2">` (or add `role="button" tabindex="0"` plus a keydown handler if the button element is not an option for styling reasons).
- **Severity rationale:** P2 — the main product image is still visible, so no information is lost; this is a navigation/a11y gap on a secondary interaction.

### [P2] Empty `#productThumbs` div still consumes a grid cell on single-image products

- **File:** `product.html:120-124` (`.product-detail-thumbs`), `js/shop.js:168-174`
- **What's wrong:** `js/shop.js` only writes thumb markup when `allImages.length > 1`. For single-image products the `#productThumbs` div exists but is empty. On desktop it still occupies the right-hand grid column (compounding Finding 1 above), and its `margin-top: 12px` applies even with no visible children.
- **Suggested fix:** After the grid-placement fix in Finding 1, also hide the thumbs container when it has no children: `.product-detail-thumbs:empty { display: none; }`.
- **Severity rationale:** P2 — purely cosmetic once Finding 1 is resolved; worth bundling into the same patch.

### [P3] `chs.html` loads `js/main.js` with no `?v=` cache-buster — inconsistent with every other page

- **File:** `chs.html:1050` — `<script src="js/main.js"></script>`
- **What's wrong:** Every other HTML page in the repo (26 pages: all root + all blog articles) loads `js/main.js?v=2`. `chs.html` is the only page that omits the version query. Next time `main.js` changes and the version is bumped to `?v=3`, chs.html visitors will keep serving the old cached file (different URL = different cache key).
- **Suggested fix:** Change to `<script src="js/main.js?v=2"></script>` to match the rest of the site.
- **Severity rationale:** P3 — passive risk, surfaces only when main.js is next bumped. Trivial to fix now while it's cheap.
