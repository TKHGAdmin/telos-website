## Findings

### 2026-11-24-1. Weekly summary email resets streak to 0 every Monday morning

- **Severity**: P2
- **Category**: functional
- **File**: `api/cron/weekly-summary.js:87-90`
- **Status**: new

**What**: The "Current Streak" shown in the Monday weekly recap email almost always reads `0 days`, regardless of how consistent the client has been, because the streak loop starts at today (`d=0`) and breaks on the first missing day.

**Why it's wrong**: The cron runs at 14:00 UTC on Mondays, which is 09:00 ET. At that moment the client has not yet done today's daily check-in, so `weekData[0][0].result` is empty, the loop breaks immediately at `d=0`, and `streak` stays at `0`. A client who logged every single day of the previous week still receives an email that says `Current Streak: 0 days`, which reads as a failure summary and undermines the recap's motivational intent.

**Suggested fix**: Either start the streak at `d=1` (yesterday) so a missing "today" does not zero out the count, or treat a missing today as "skip" rather than "break". Smallest diff:

```js
// Count streak (from yesterday backwards; today may not be logged yet when the email runs)
for (var d = 1; d < 7; d++) {
  if (weekData[0][d] && weekData[0][d].result) streak++;
  else break;
}
```

### 2026-11-24-2. Dead `everfitUrl` API surface after Everfit removal

- **Severity**: P3
- **Category**: functional
- **File**: `api/client/me.js:28`, `api/dashboard/clients.js:119`
- **Status**: new

**What**: `api/client/me.js` still returns `everfitUrl: process.env.EVERFIT_URL || ''` on the client profile, and `api/dashboard/clients.js` still accepts an `everfitUrl` field on PATCH. Per `CLAUDE.md` ("Everfit removed: Training is now fully in-app"), no consumer reads this value anymore - `client-dashboard.html` and `thomas.html` have zero references to `everfit` or `Everfit`.

**Why it's wrong**: The API surface implies a feature that no longer exists. An admin reading `clients.js` will see a hook for Everfit and assume it is still wired through, when in reality setting it has no effect. The `EVERFIT_URL` env var in the response is dead weight on every `/api/client/me` call.

**Suggested fix**: Drop `everfitUrl` from the `me.js` response and remove the `body.everfitUrl` branch in `clients.js`. Optionally sweep stored client records for the leftover field in a one-off script, or leave it to decay since nothing reads it.
