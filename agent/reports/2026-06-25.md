# Telos Bug Hunter - 2026-06-25

**Focus:** Functional
**Bugs found:** 2
**Summary:** Weekly summary email reports streak=0 every Monday morning because today's daily log doesn't exist when the cron runs. Quiz allows rapid-click double-counting that both inflates pillar scores and skips a subsequent question.

---

## Bug ID — 2026-06-25-01
- **Severity:** P1
- **File:** `api/cron/weekly-summary.js:86-90`
- **What's wrong:** The weekly-summary cron runs Monday 14:00 UTC (10:00 EDT / 9:00 EST). The streak counter starts at `d=0` (today, in UTC) and breaks at the first day with no daily log. At 10 AM EDT on a Monday almost no client has logged today's check-in yet, so `weekData[0][0].result` is null, the loop breaks immediately, and the email shows `Current Streak: 0 days` regardless of the client's actual streak through Sunday.
- **Repro / Trace:**
  ```js
  // weekly-summary.js:86-90
  for (var d = 0; d < 7; d++) {
    if (weekData[0][d] && weekData[0][d].result) streak++;
    else break;
  }
  ```
  Today (d=0) is Monday. The cron sends emails at 10 AM EDT before users complete their Monday daily check-in. The streak fails on the first iteration. A client with a true 30-day streak through Sunday receives an email saying their streak is 0.
- **Expected:** The streak should reflect activity through yesterday (Sunday) at minimum. Either start the loop at `d=1` if today's log is missing, or count from the most recent logged day backwards.
- **Fix sketch:**
  ```js
  // Skip today if not yet logged; only break on a real gap.
  var startD = (weekData[0][0] && weekData[0][0].result) ? 0 : 1;
  for (var d = startD; d < 7; d++) {
    if (weekData[0][d] && weekData[0][d].result) streak++;
    else break;
  }
  ```

## Bug ID — 2026-06-25-02
- **Severity:** P2
- **File:** `js/quiz.js:198-218`
- **What's wrong:** `handleAnswerSelect` adds points and schedules a 400ms auto-advance, but does not disable the other option buttons after the first click. A user who taps two options within 400ms (common on mobile due to fat-finger or sticky touches) adds BOTH option point values to the same pillar AND triggers two `setTimeout` callbacks, each calling `quiz.currentQuestion++` and `renderQuestion()`. The result: the pillar score is inflated, and the next question is silently skipped (it renders briefly then immediately advances again).
- **Repro / Trace:**
  ```js
  // quiz.js:198-218
  function handleAnswerSelect(button, option, pillar) {
    button.style.borderColor = '#C9A84C';
    quiz.scores[pillar] += option.points;        // no guard
    setTimeout(() => {
      if (quiz.currentQuestion < 7) {
        quiz.currentQuestion++;                  // fires per click
        renderQuestion();
      } else { ... }
    }, 400);
  }
  ```
  Steps: open `/` or `/pricing`, start the quiz, on Question 1 tap option A then tap option B within 400ms. Pillar 0 receives `A.points + B.points`. Question 2 renders briefly, then a second timeout fires and jumps to Question 3, leaving Question 2's pillar at 0. Total score is wrong; tier and weakest-pillar callouts are wrong; the lead-capture/dashboard record persists the corrupted scores via `/api/submit-quiz`.
- **Expected:** First click should lock the question — disable all option buttons in that question and ignore subsequent taps until `renderQuestion()` for the next question runs.
- **Fix sketch:**
  ```js
  function handleAnswerSelect(button, option, pillar) {
    if (button.dataset.locked) return;
    optionsContainer = quizQuestionCard.querySelector('.quiz-options');
    optionsContainer.querySelectorAll('.quiz-option').forEach(b => {
      b.dataset.locked = '1';
      b.style.pointerEvents = 'none';
    });
    button.style.borderColor = '#C9A84C';
    quiz.scores[pillar] += option.points;
    setTimeout(() => { /* advance as before */ }, 400);
  }
  ```
