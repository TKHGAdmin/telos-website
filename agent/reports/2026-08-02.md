## P1-2026-08-02-01 - Product detail page: thumbnails render in the info column, product info squeezed to half width

**Severity:** P1
**Area:** product.html (shop stack, /product route)
**Introduced by:** commit `f5cb8c4` - "feat: add image gallery with thumbnails on product page" (2026-05-20)
**Status:** unresolved

### What's wrong

`product.html:765-780` defines the product detail as a 2-column CSS grid (`grid-template-columns: 1fr 1fr` at `product.html:107`) with **three** direct children:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-image" id="productImage"></div>
  <div class="product-detail-thumbs" id="productThumbs"></div>
  <div class="product-detail-info"> ... title, price, add-to-cart, description ... </div>
</div>
```

With 3 items in a 2-column grid and no explicit `grid-area` / `grid-row` assignments, grid auto-placement lays them out as:

| Column 1 | Column 2 |
|---|---|
| `.product-detail-image` | `.product-detail-thumbs` |
| `.product-detail-info` (only half width) | *(empty)* |

**Intended** layout (based on `.product-detail-thumbs` having `flex-direction: row; margin-top: 12px` in the CSS, and the info column containing the title/price/CTA):

| Column 1 | Column 2 |
|---|---|
| `.product-detail-image` | `.product-detail-info` |
| `.product-detail-thumbs` (row of thumbnails under the image) | |

### User impact

On any product with more than one image (which is the whole point of the gallery feature that just shipped):

1. The right side of the fold above the CTA - where a shopper expects to see the title, price, and *Add to Cart* button - shows a row of small square thumbnails instead.
2. The product title, price, CTA, and long description are pushed **below** the main image and crammed into the left half of the page, leaving the right half blank.
3. Add to Cart is significantly less discoverable. This directly hurts conversion on the very page whose only job is to close a sale.

Mobile (< 768px) is unaffected because the media query collapses to `grid-template-columns: 1fr` and the source order (image → thumbs → info) is actually reasonable in a single column.

Products with 0 or 1 image also render acceptably: single-image products still create the empty `#productThumbs` div (still a grid item), but with no children it collapses to no visible height, so info correctly appears in col 2 row 1.

### How to reproduce

1. Ensure a Shopify product with 2+ images exists in the connected store.
2. Load `/product?p=<handle-of-that-product>` on a viewport wider than 768px.
3. Observe: thumbnails sit where the title should be; info column is at half width below the image.

### Suggested fix (do not implement - report only)

Either wrap the image + thumbs in a single grid item:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-media">
    <div class="product-detail-image" id="productImage"></div>
    <div class="product-detail-thumbs" id="productThumbs"></div>
  </div>
  <div class="product-detail-info"> ... </div>
</div>
```

Or pin the info panel with `grid-column: 2; grid-row: 1 / span 2;` and let image/thumbs stack in column 1.

## P2-2026-08-02-02 - `shop.html` cache-busting version stuck at `?v=1` while `product.html` is on `?v=2`; returning visitors get stale `shop.js`

**Severity:** P2
**Area:** shop.html (asset versioning)
**Introduced by:** commit `f5cb8c4` (bumped product.html to `?v=2`, did not touch shop.html)
**Status:** unresolved

### What's wrong

`shop.html:841` loads `js/shop.js?v=1`. `product.html:822` loads the same file as `js/shop.js?v=2`. Both pages use the same `js/shop.js`, which was materially changed in `f5cb8c4` (added the `switchProductImage` function and image-gallery rendering).

### User impact

The `?v=` query is the site's cache-busting convention (per CLAUDE.md: "CSS cache busting: Stylesheet references use `?v=N` query param. Bump the version on all pages when changing style.css"). Because `shop.html` still requests `?v=1`, any returning visitor whose browser cached `js/shop.js?v=1` will continue to run the old file on `/shop` until they hard-refresh, even though the fresh version is being served (and pulled) on `/product`. Symptoms of the stale JS on `/shop` today are minor (older but still-functional shop code), but the pattern guarantees future changes to `shop.js` will silently fail to reach returning `/shop` visitors while working fine on `/product`.

### How to reproduce

```
grep -n "shop.js" shop.html product.html
# shop.html:841:  <script src="js/shop.js?v=1"></script>
# product.html:822:  <script src="js/shop.js?v=2"></script>
```

### Suggested fix (do not implement - report only)

Bump `shop.html` to `?v=2` (or higher) and treat every future `js/shop.js` edit as needing both files updated together. Longer-term, unifying to a single build/versioning constant would prevent recurrence.
