## Findings

### [P2] `escapeHtml()` in shop.js does not escape quotes — breaks HTML for any product with `"` or `'` in its title

- **Severity:** P2
- **Area:** `js/shop.js:509-514`
- **Repro:**
  1. Create a Shopify product titled e.g. `The 12" Ultimate Guide`.
  2. Load `/shop` or `/product?p=...`.
  3. The `<img alt="…">` tag closes after `The 12` because `escapeHtml` returns the raw `"` and the browser treats it as the attribute terminator. Everything after becomes stray tokens: `<img src="…" alt="The 12" Guide">`. The image loses its alt; screen readers get garbage; if a value ever contained `on…="…"` it would inject attributes.
- **Impact:** Any Shopify product title, product type, or line-item title containing `"` (very common in fitness for measurements like `12"`, `24" bar`) or `'` renders broken. The five HTML-attribute sites are:
  - `js/shop.js:166` — product-detail hero `<img alt="…">`
  - `js/shop.js:276` — product-card `<img alt="…">`
  - `js/shop.js:432` — cart-drawer line-item `<img alt="…">`
  - `js/shop.js:170-172` — thumbnail `<img alt="…">` (plus an `onclick="switchProductImage(this, '<img.src>')"` where `img.src` is embedded in a JS string literal with no escaping — same class of issue)
  - `js/shop.js:291` — `<button … onclick="addToCart(this, '<variant.id>')">` — same JS-in-attribute pattern
- **Root cause:** `escapeHtml` uses text-node serialization (`div.appendChild(document.createTextNode(str)); return div.innerHTML;`). Per the HTML spec, that path only escapes `&`, `<`, `>`, and `U+00A0` — never `"` or `'`. Safe for text content, unsafe for attribute values.
- **Suggested fix:**
  ```js
  function escapeHtml(str) {
    if (str == null) return '';
    return String(str)
      .replace(/&/g, '&amp;')
      .replace(/</g, '&lt;')
      .replace(/>/g, '&gt;')
      .replace(/"/g, '&quot;')
      .replace(/'/g, '&#39;');
  }
  ```
  Also stop interpolating raw values into `onclick="…"` handlers (lines 170, 291, 440, 442, 445). Prefer `addEventListener` with data-attributes, or at minimum wrap the interpolated value in a helper that escapes for a JS-string-inside-an-HTML-attribute context.
- **Evidence:** `js/shop.js:509-514` (function definition); `js/shop.js:166,170-172,276,291,432,440-445` (call sites).

### [P2] `hyrox-predictor.html` is missing the site footer

- **Severity:** P2
- **Area:** `hyrox-predictor.html`
- **Repro:** Visit `/hyrox-predictor`. Scroll to the bottom. There is no footer — the page ends immediately after `</main>` and drops straight into the `<script>` block. Every other public marketing page (`index.html`, `pricing.html`, `product.html`, `shop.html`, `protein-calculator.html`, `resources.html`, `chs.html`) renders the standard `<footer class="site-footer">` with brand copy, quick links, socials, and the consultation CTA.
- **Impact:** Users who reach the hyrox tool via a search-engine landing or a direct link lose the site's Instagram / email / "Book a Free Consultation" CTA — the standard funnel exit on every other page. It also breaks visual consistency. The tool is a lead magnet; the missing footer removes the natural conversion path after they've engaged.
- **Suggested fix:** Copy the `<footer id="footer" class="site-footer">…</footer>` block from `protein-calculator.html:725-731` (or from any other tool page) and paste it between `</main>` (line 698) and `<script>` (line 700).
- **Evidence:** `hyrox-predictor.html:698-700` — `</main>` immediately followed by `<script>` with nothing between. `protein-calculator.html:725-731` for the reference footer block.
