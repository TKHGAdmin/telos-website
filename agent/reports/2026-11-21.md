## Bug 1 - P1 - Homepage mobile nav clips "Book a Call" CTA

**Where:** `css/style.css:2783-2786` + `css/style.css:496-503` + `css/style.css:2779-2781`

**What happens:**

As soon as a mobile user taps the hamburger on `/` (index.html), the "Tools" submenu (Execution Score Quiz, Protein Calculator, Hyrox Predictor, Resources, FAQ) renders expanded even though the dropdown's `active` class has not been added. That already-expanded submenu pushes the overall menu content past its own `max-height: 500px; overflow: hidden` cap, and the final `<li>` - the gold "BOOK A CALL" CTA button - is clipped completely out of view.

**Why it happens:**

Two CSS rules fight, and specificity hands the win to the wrong one:

```css
/* style.css:496 - intends dropdown collapsed by default */
.mobile-dropdown-menu { display: none; }               /* specificity 0,1,0 */
.mobile-dropdown.active .mobile-dropdown-menu {
  display: block;                                      /* specificity 0,2,0 */
}

/* style.css:2783 - but this generic descendant selector also matches
   .mobile-dropdown-menu because it is a <ul> inside .mobile-menu */
.mobile-menu ul { display: flex; flex-direction: column; ... } /* 0,1,1 */
```

`.mobile-menu ul` (0,1,1) beats `.mobile-dropdown-menu` (0,1,0), so the dropdown is always `display: flex` on mobile. The "Tools" toggle chevron still rotates when tapped (because `.active` is added), but the items were never hidden.

**Verification:**

```
Playwright (iPhone 13, 390x844, localhost):
  State: hamburger just tapped, Tools NOT tapped
    .mobile-dropdown-menu computed display: flex   <- should be "none"
    .mobile-dropdown.active present:              false
    BOOK A CALL <a> bottom:                        631px
    .mobile-menu bottom (max-height 500 + top 70): 570px
    BOOK A CALL visible in menu:                   NO (clipped by overflow:hidden)
```

Screenshot: open the homepage on a phone, tap the hamburger - the menu ends at "Client Login" and the gold CTA is gone.

**Suggested fix (small, targeted):**

Either raise the specificity of the collapse rule, or narrow the flex rule. Minimal diff:

```css
/* css/style.css:496 */
.mobile-menu .mobile-dropdown-menu { display: none; }  /* now 0,2,1 beats 0,1,1 */
.mobile-menu .mobile-dropdown.active .mobile-dropdown-menu { display: block; }
```

That restores the intended collapsed-by-default behavior and the menu content fits inside the 500px cap with room to spare. (The 500px cap itself is also worth revisiting - it's just large enough for the current link set and will start clipping again the next time an item is added.)

**Why this is P1, not P2:** every first-time mobile visitor to the homepage loses the primary conversion CTA from the primary navigation. Mobile is the dominant channel for Instagram-sourced traffic (per the IG-profile avatar baked into the nav), and "Book a Call" goes straight to the Growth-tier Calendly.

## Bug 2 - P2 - Pricing page: duplicate ghost brand under the quiz overlay

**Where:** `pricing.html:640` (main is `display:none`) + `pricing.html:860-890` (footer markup) + `pricing.html:31-46` (overlay CSS, `background: rgba(8,8,8,0.97)`, `z-index: 10000`)

**What happens:**

Before the Execution Score Quiz is completed, `#pricingContent` (the entire pricing page body) is `display: none`. The footer is therefore the next element in flow directly after the nav. With the quiz overlay on top (nearly opaque but not fully), the footer's large uppercase "TELOS FITNESS" wordmark renders directly below the real nav logo, both dimmed to ~3% visibility. The visual effect is a duplicate brand ghost behind the quiz modal. (A narrow strip of footer links wrapping down the left margin is also visible through the backdrop.)

**Verification:**

```
Playwright (iPhone 13):
  Visible "TELOS FITNESS" elements:
    .nav-logo                 top=19  h=32  w=102
    footer <span> (brand)     top=49  h=32  w=358   <- ghost directly below
```

Screenshot in scratchpad: `screens/iphone-pricing-top.png`.

**Suggested fix (pick one):**

- Give `.quiz-overlay` a fully opaque background (`rgba(8,8,8,1)` or `#080808`) - cleanest, removes the ghosting instantly.
- Or wrap the footer in a container that is `display:none` until the quiz completes (parallel to how `#pricingContent` is hidden), so there is nothing below the nav to ghost through.
- Or just `overflow: hidden` on `body` while the overlay is visible.

**Why P2, not P1:** the page is still functional, and the quiz CTA is the correct primary action. It just looks half-broken.

## Bug 3 - P2 - Lead-capture form inputs have no accessible label

**Where:** `index.html:577-579` and `pricing.html:591-593` (identical markup in both)

**What happens:**

```html
<input type="text"  name="name"  placeholder="First name"   required ...>
<input type="email" name="email" placeholder="Email address" required ...>
<input type="tel"   name="phone" placeholder="Phone number"          ...>
```

No wrapping `<label>`, no sibling `<label for="...">`, no `aria-label`. The only visible affordance is the placeholder, which (a) is not announced reliably by screen readers as a label, (b) disappears the moment the field gains focus, so a user who paused mid-typing can't recover the field's purpose, and (c) fails WCAG 2.1 SC 3.3.2 Labels or Instructions.

This is the same form that gates personalized pricing on `/pricing`, so it's the first form a committed prospect fills in.

**Suggested fix:** add `aria-label="First name"` / `aria-label="Email address"` / `aria-label="Phone number"` to each input. Minimum change; keeps the current visual design.

## Bug 4 - P3 - Tool-page labels not associated with inputs

**Where:** `protein-calculator.html:545-574` and the equivalent markup in `hyrox-predictor.html`.

Labels like `<label>Body Weight (lbs)</label>` are siblings of inputs like `<input id="weight">` with no `for="weight"`. Visually fine, but clicking the label doesn't focus the field and screen readers don't pair them. Fix: add `for="weight"` etc. to each label (or wrap the input).

## Bug 5 - P3 - Client dashboard icon-only buttons lack aria-label

**Where:** `client-dashboard.html:1533`, `1537`, `1539`, `1605`, `1685` (modal close X, check-in date prev/next arrows).

Each is `<button class="..." onclick="..."><svg>...</svg></button>` with no accessible name. Add `aria-label="Close"` / `aria-label="Previous day"` / `aria-label="Next day"`. Low urgency because the dashboard is behind client login and already ships a lot of a11y debt per CLAUDE.md "Known Limitations", but these are two-character fixes.

## Things checked and ruled out (so I don't re-flag them tomorrow)

- `coaches.html` comparison table (`.cmp`, `min-width: 780px`) is NOT a mobile overflow bug - it's wrapped in `.cmp-wrap { overflow-x: auto }` and `body { overflow-x: clip }` prevents page-level horizontal scroll. Intentional horizontal-scroll pattern for the comparison matrix.
- Hero orbs on index.html extend beyond the viewport but `overflow-x` on the hero/body contains them. Not a real scroll bug.
- Known limitations already in CLAUDE.md (tool pages missing main.js, Whop iframe on iOS Safari, todayStr UTC bug, SW cache bump) were intentionally not re-flagged.
- Shopify Buy SDK console error on `/product` and `/shop` only reproduced because the local test sandbox blocks the SDK CDN (TUNNEL_CONNECTION_FAILED). Expected to work in production. Did not verify against live site.
- The `coaches.html` blue accent (`#74CCFF`) deviating from the site gold (`#C9A84C`) is intentional per the file's inline design notes - a deliberate separate "Glass ice" theme for the coaches landing page.
