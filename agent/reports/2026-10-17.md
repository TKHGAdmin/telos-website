## Findings

### P2 — Admin session HMAC verified with non-timing-safe `!==` comparison

**File / line:** `api/lib/auth.js:27`

**What it is**
`verifyToken()` compares the user-supplied HMAC signature to the recomputed expected signature with a plain string `!==`:

```js
// api/lib/auth.js
function verifyToken(token) {
  if (!token) return false;
  const parts = token.split('.');
  if (parts.length !== 2) return false;
  const [payload, signature] = parts;
  const expected = crypto
    .createHmac('sha256', SESSION_SECRET)
    .update(payload)
    .digest('hex');
  if (signature !== expected) return false;   // <-- line 27, non-constant-time
  ...
}
```

JavaScript's `!==` on strings short-circuits at the first differing character, which leaks per-byte timing information about the correct signature.

**Why it matters**
1. This is the gate for every `/thomas` dashboard request and every `/api/dashboard/*` endpoint — i.e. the entire admin surface (pipeline, clients, revenue, Charleston applications, ad spend, PII in quiz leads).
2. The file *claims* the design is timing-safe. `CLAUDE.md` describes `auth.js` as "HMAC-signed, timing-safe password check". The password check (`verifyPassword`, line 58) does use `crypto.timingSafeEqual`. The **token** check does not — an internal inconsistency, not just an oversight.
3. The adjacent `api/lib/client-auth.js:49` already does this correctly for the client cookie:
   ```js
   if (!crypto.timingSafeEqual(a, b)) return null;
   ```
   So the fix is a straight port of that pattern.

**Exploitability (honest):** Network jitter from the browser → Vercel Edge → Node runtime almost certainly dwarfs the nanosecond-scale timing delta of `!==` for a single request, so a remote attack is not practical in the near term. Rated P2, not P1, for that reason. It is still a real, fixable defect in security-critical code and worth closing before the admin surface grows.

**Suggested fix**
Replace line 27 with the same pattern used in `client-auth.js`:

```js
const sigBuf = Buffer.from(signature, 'hex');
const expBuf = Buffer.from(expected, 'hex');
if (sigBuf.length !== expBuf.length) return false;
if (!crypto.timingSafeEqual(sigBuf, expBuf)) return false;
```

**Reproduction**
Static review of `api/lib/auth.js:27`. Compare against `api/lib/client-auth.js:46-49` which handles the equivalent check correctly.

**Scope of fix:** 4 lines in one function. No API or storage changes. No cookie invalidation needed — existing valid sessions continue to work.
