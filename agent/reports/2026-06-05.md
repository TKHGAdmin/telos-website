# Telos Bug Hunter Report — 2026-06-05

**Focus:** Functional
**Bugs found:** 2

First run of the Bug Hunter. Today's focus was Functional, with attention
on the freshest surfaces — the new shop/cart/product-detail flow (last
five commits) and the long-lived quiz lead-capture path. Two real,
reproducible issues stood out: a broken product-detail desktop layout
introduced by the new image-gallery markup, and a duplicate-submission bug
in the quiz that fires every time a user retakes it. The Shopify
Storefront token in `js/shop.js` is intentionally public and is NOT
reported (logged as a known false-positive in `learnings.md`).

## Bugs

### BUG-20260605-01 — P1 — Product detail page layout broken on desktop (info shoved below image)

**Where:** `product.html:765-780`, with related CSS at `product.html:100-115`

**Repro:**
1. Open any product detail page on desktop (`/product?p=<handle>`).
2. Observe the right half of the page is empty and the title / price / Add-to-Cart / description column renders BELOW the image instead of beside it.
3. For products with more than one image, the thumbnail strip renders in the right column where the info should be.

**Why it matters:** The product detail page is the only place users see the buy CTA and the full description. With the info column pushed under the image, the primary "Add to Cart" button drops well below the fold on desktop, breaking the core conversion flow for the entire shop. This was introduced by commit `f5cb8c4` ("feat: add image gallery with thumbnails on product page").

**Root cause:** `.product-detail.loaded` is `display: grid; grid-template-columns: 1fr 1fr` (two columns). It now contains three direct children — `#productImage`, `#productThumbs`, and `.product-detail-info`. CSS-Grid auto-placement therefore puts the image in (row 1, col 1), the thumbs in (row 1, col 2 — where info should be), and info in (row 2, col 1). The thumbs div is rendered even when empty, so the bug manifests for every product, not just multi-image ones.

**Suggested fix:** Wrap `#productImage` and `#productThumbs` in a single `.product-detail-left` container so the grid sees only two children (left = image+thumbs stacked, right = info).

### BUG-20260605-02 — P2 — Quiz "Retake" leaks event listeners → duplicate quiz submissions

**Where:** `js/quiz.js:215-275` (`setupLeadCapture()` adds a fresh `click` listener each time it runs), with retake hook at `js/quiz.js:397` and `js/quiz.js:416-442` (`resetQuiz()`)

**Repro:**
1. Visit `/` or `/pricing`, complete the Execution Score Quiz, enter name/email/phone, click "See My Score". One `POST /api/submit-quiz` fires (verify in DevTools → Network).
2. Click "Retake Quiz" on the results screen.
3. Walk through the eight questions again, fill in the lead-capture form, click "See My Score" once.
4. Observe TWO `POST /api/submit-quiz` requests with identical bodies. Each retake compounds: after N retakes, one submit click sends N+1 identical submissions.

**Why it matters:** Every retake silently pollutes the `quiz_submissions` ZSET in Upstash, the leads pipeline in `/thomas`, and dashboard analytics with duplicate rows for the same person. It also doubles the rate-limit consumption per user and triples (or worse) the localStorage writes. No user-facing harm, but the business dashboard's lead numbers are wrong.

**Root cause:** `setupLeadCapture()` is invoked every time the user reaches Q8 (after Q1-Q8 in `handleAnswerSelect` at `js/quiz.js:213-215`). On each invocation it calls `submitBtn.addEventListener('click', ...)` without removing any previous handler. `resetQuiz()` does `form.reset()` but doesn't replace the button node or detach the listener. The retake button (`js/quiz.js:397`) and the view-pricing button (`js/quiz.js:403`) accumulate listeners the same way, but those are idempotent so they're cosmetic.

**Suggested fix:** Either (a) move the listener registration outside `setupLeadCapture` and run it once on DOM-ready, or (b) clone-and-replace the submit button at the top of `setupLeadCapture` to strip any prior handlers, then attach.
