## P1-01 — Product detail page renders in a broken 2-column layout

**File:** `product.html:766-780` (change introduced in commit `f5cb8c4`, "feat: add image gallery with thumbnails on product page", 2026-05-20)

**What's wrong**

The product-detail container is a two-column grid when loaded:

```css
.product-detail.loaded {
  display: grid;
  grid-template-columns: 1fr 1fr;
}
```

It has three direct children in this order:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-image" id="productImage"></div>
  <div class="product-detail-thumbs" id="productThumbs"></div>   <!-- added in f5cb8c4 -->
  <div class="product-detail-info"> … title, price, add-to-cart, description … </div>
</div>
```

With two grid columns and three items, CSS Grid flows them left-to-right, top-to-bottom:

| | col 1 | col 2 |
|---|---|---|
| row 1 | product image | thumbs |
| row 2 | product info (title / price / CTA / description) | *(empty)* |

So on every viewport ≥ 769 px (the desktop breakpoint) the product info block — including the Add-to-Cart button and price — gets pushed **below** the image instead of appearing next to it. The right column below the thumbs is empty whitespace. Any product with more than one image also gets thumbnails stranded in the top-right corner where the title should be.

The pre-thumbnail version (before commit `f5cb8c4`) had only two children (`.product-detail-image` + `.product-detail-info`) and rendered correctly. The commit added `<div id="productThumbs">` as a third sibling without wrapping it or the image in a shared column container, breaking the intended layout.

**Reproduction**
1. Deploy current `main` and open any product URL, e.g. `/product?p=<any-handle>`.
2. Resize the viewport to ≥ 769 px.
3. Observe: the image occupies the top-left cell; the "Add to Cart" button and description are below the image (row 2, left) rather than in the right column.

**Suggested fix (for Thomas's review — do not apply automatically)**

Wrap the image + thumbs in a single left-column container so the grid still sees two children:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-media">
    <div class="product-detail-image" id="productImage"></div>
    <div class="product-detail-thumbs" id="productThumbs"></div>
  </div>
  <div class="product-detail-info"> … </div>
</div>
```

(No `.product-detail-media` styles needed beyond what already exists — a plain block wrapper works.)

**Impact:** This is the primary purchase surface of the shop. Every product detail page on desktop is visually broken until this is fixed.

## P3-01 — `js/shop.js` cache-bust version is out of sync between shop.html and product.html

**Files:**
- `shop.html:841` → `<script src="js/shop.js?v=1"></script>`
- `product.html:822` → `<script src="js/shop.js?v=2"></script>`

**What's wrong**

Both pages load the same `js/shop.js` file, but pin different `?v=` cache-bust values. The convention in `CLAUDE.md` ("CSS cache busting: Stylesheet references use `?v=N` query param. Bump the version on all pages when changing style.css.") applies here too by extension — the whole point of the query param is that all pages agree on the current version so browsers invalidate together.

Because the versions are out of sync, a user who visits `product` (cached at v=2) and then `shop` (v=1) will hit whichever version their browser cached first. When `shop.js` is next updated, if only one page's number is bumped, users may see stale JS on the other.

**Reproduction**
1. Update `js/shop.js` and bump only `shop.html`'s `?v=` (or only `product.html`'s). Deploy.
2. A returning user who last hit the un-bumped page will keep serving the old JS from cache.

**Suggested fix**

Align both pages on the same version and bump them together going forward. Since `product.html` has the higher value, sync `shop.html` up to `?v=2` now.

**Impact:** Low. No live user-visible symptom today, but the cache-busting mechanism is quietly broken between the two pages, which will cause a hard-to-diagnose "some users see the old shop JS" report the next time `shop.js` changes.
