## Findings

### [P3] `shop.html` left on `js/shop.js?v=1` after the gallery bump

- **File**: `shop.html:841`
- **Severity**: P3 (tech debt / convention violation)
- **Category**: Functional / cache-busting

**What's wrong**

Commit `f5cb8c4` ("feat: add image gallery with thumbnails on product page") modified `js/shop.js` and bumped **only** `product.html` to `js/shop.js?v=2`. `shop.html` is still at `js/shop.js?v=1` even though it loads the exact same shared file:

```
shop.html:841     <script src="js/shop.js?v=1"></script>
product.html:822  <script src="js/shop.js?v=2"></script>
```

`CLAUDE.md` codifies the convention: *"CSS cache busting: Stylesheet references use `?v=N` query param. Bump the version on all pages when changing style.css."* The convention applies to shared JS by analogy and is already respected for `main.js?v=2` everywhere except `chs.html` (see next finding).

**Impact today**: nil — both pages fetch the same physical file; the different cache keys just mean a one-off double download for users who visit both pages while cached. **Impact tomorrow**: the next edit to `shop.js` that bumps `shop.html` to `?v=3` without touching `product.html` will leave `product.html` serving a stale cached version, and the mismatch is now hidden by this one.

**Reproduce / verify**

```bash
grep -n 'shop.js' shop.html product.html
```

**Fix**: in `shop.html:841`, change `js/shop.js?v=1` to `js/shop.js?v=2`.

### [P3] `chs.html` loads `js/main.js` with no `?v=N` suffix

- **File**: `chs.html:1050`
- **Severity**: P3 (tech debt / convention violation)
- **Category**: Functional / cache-busting

**What's wrong**

Every other public page that references `js/main.js` uses the versioned form `js/main.js?v=2` (23 blog pages + `index.html`, `pricing.html`, `resources.html`, `shop.html`, `product.html`, `privacy.html`, `terms.html`, `set-password.html`). `chs.html` is the single outlier:

```
chs.html:1050     <script src="js/main.js"></script>
<everything else> <script src="js/main.js?v=2"></script>
```

**Impact today**: Charleston-landing visitors with a cached `main.js` from an earlier `?v=2` fetch will keep that cached copy indefinitely, even when `main.js` is next updated and the rest of the site is bumped to `?v=3`. Only the `/chs` page will be stuck on the stale script. Hamburger / scroll animation behaviour on `/chs` can therefore quietly diverge from the rest of the site after any `main.js` change.

**Reproduce / verify**

```bash
grep -h 'js/main.js' *.html blog/*.html | sort -u
# Expected: one line.  Observed: two lines, chs.html is unique.
```

**Fix**: in `chs.html:1050`, change `js/main.js` to `js/main.js?v=2` (matching the rest of the site).
