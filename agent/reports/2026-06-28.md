## P2 — Stale `shop.js` for returning visitors to `/shop`

**Files:**
- `shop.html:841` → `<script src="js/shop.js?v=1"></script>`
- `product.html:822` → `<script src="js/shop.js?v=2"></script>`

**Problem:** Both pages load the same file `js/shop.js`, but with **different cache-busting versions**. `product.html` was bumped to `?v=2` (commit `f5cb8c4 feat: add image gallery with thumbnails on product page` — which modified `js/shop.js`). `shop.html` was not bumped.

**Why it affects real users:** Any returning visitor whose browser cached `js/shop.js?v=1` will keep using the stale version when they revisit `/shop`. The recent commits to `shop.js` added the click-to-detail handler on product cards (`card.addEventListener('click', …)` navigating to `product?p=…`), the `addToCartFromDetail` / `loadProductDetail` functions, and the `switchProductImage` gallery handler. A returning visitor on `/shop` with the cached v=1 file won't get the click-to-detail behavior — clicking a product card will appear dead/inert. The product detail page works for them only because `product.html` correctly bumped the version.

**Repro:**
1. Visit `/shop` while `shop.js?v=1` is the live deploy → browser caches `shop.js?v=1`.
2. After a deploy that updates `shop.js`, visit `/shop` again. Browser sees the same `?v=1` URL → serves cached file → user runs old JS.
3. Click a product card — nothing happens (no navigation to product detail).

**Fix:** Bump `shop.html:841` to `?v=2` (or higher) so the URL changes on every `shop.js` update. Best long-term fix: keep both pages' cache-bust versions in lockstep, or move to a content-hash filename.

**Severity rationale:** P2 (not P1) because (a) new visitors are unaffected, (b) hard-reload clears it, (c) on `/shop` the broken click-handler still has the "Add to Cart" button working — only the navigation-to-detail flow is degraded. Still a real regression for the recurring-visitor segment, which is the most engaged audience.

## P3 — `chs.html` loads `js/main.js` without cache-busting query

**File:** `chs.html:1050` → `<script src="js/main.js"></script>`

**Problem:** Every other page that loads `main.js` uses `?v=2` (verified across 28 pages — `index.html`, `pricing.html`, `product.html`, `shop.html`, `resources.html`, all 23 blog articles). `chs.html` is the only outlier.

**Why it matters:** Same caching trap as above, but lower impact — `main.js` handles nav, hamburger, scroll animations. A stale cached copy on `/chs` returning visitors could miss new nav behavior. Lower priority because the file changes infrequently.

**Fix:** Add `?v=2` to match the rest of the site.
