## BUG-2026-08-14-01 — P1 — Product detail page: image gallery breaks the two-column layout

**Files**
- `product.html:105-108` (grid CSS)
- `product.html:764-780` (DOM)

**Introduced by**: commit `f5cb8c4` (feat: add image gallery with thumbnails on product page)

### What's wrong

`.product-detail.loaded` is a two-column CSS grid, but the DOM under `<div class="product-detail" id="productDetail">` has **three direct children**:

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-image" id="productImage"></div>   <!-- grid cell 1,1 -->
  <div class="product-detail-thumbs" id="productThumbs"></div> <!-- grid cell 1,2 -->
  <div class="product-detail-info"> ... </div>                 <!-- grid cell 2,1 -->
</div>
```

With `grid-template-columns: 1fr 1fr`, CSS Grid places these left-to-right, top-to-bottom:

```
Row 1: [ product image ]  [ empty thumbs div ]
Row 2: [ product INFO   ]  [ empty            ]
```

The intended layout — image + thumbs stacked in the left column, info card in the right column — is impossible with this DOM. The `.product-detail-thumbs` CSS even sets `margin-top: 12px`, confirming the designer expected the thumbs to sit **below** the image, not beside it.

Concrete visible symptoms on `/product?p=<any-handle>` at widths ≥ 769px:
1. When the product has ≥ 2 images: the thumbnails render in the **right column** where the price / Add-to-Cart / description are supposed to be, and the info block wraps to a **second row** under the main image, taking only the left column and leaving a huge blank area on the right.
2. When the product has only 1 image (or no thumbs are rendered), `#productThumbs` is still an empty `<div>` and still consumes grid cell 1,2 — pushing the info to row 2 identically. Users see a giant image on the left and the price + Add-to-Cart shoved into a narrow column below, with the right half of the page empty.

Under 768px the media query collapses to a single column, so mobile is unaffected. Desktop and tablet are broken for every product.

### Reproduce

1. `npx serve -l 3000 .` in the repo root.
2. Open `http://localhost:3000/shop` and click any product card (or go directly to `/product?p=<handle>` for any real handle).
3. Resize the window ≥ 769px wide.
4. Observe: the price, Add to Cart button, and description are pushed under the image on the left half; the right half of the page is empty. If the product has multiple images, the thumbnail row appears alone on the right of row 1.

### Failure scenario (customer)

A customer clicks a product from the shop grid, lands on `/product?p=<handle>` on desktop, and sees the "Add to Cart" button crammed under a huge product image in the left half of the page while the right half is blank. On multi-image products the thumbnails are also detached from their image. This is on the primary conversion path for the newly-launched shop — it undermines the premium hotel-site aesthetic the rest of the site works to project, and makes the Add to Cart target visually harder to find.

### Fix (proposed — for Thomas to approve, not to be applied by the bug hunter)

Two straightforward options:

**Option A — wrap image + thumbs in a container** (recommended, no CSS change needed):

```html
<div class="product-detail" id="productDetail">
  <div class="product-detail-media">
    <div class="product-detail-image" id="productImage"></div>
    <div class="product-detail-thumbs" id="productThumbs"></div>
  </div>
  <div class="product-detail-info"> ... </div>
</div>
```

**Option B — span the info across the second grid row** (leaves DOM alone):

```css
.product-detail.loaded {
  display: grid;
  grid-template-columns: 1fr 1fr;
  grid-template-areas:
    "image info"
    "thumbs info";
}
.product-detail-image  { grid-area: image; }
.product-detail-thumbs { grid-area: thumbs; }
.product-detail-info   { grid-area: info; }
```

Option A is cleaner and requires no CSS changes.

### Confidence

**High.** Verifiable purely by reading `product.html` — three grid children in a two-column grid always produce the broken layout described above. No runtime test needed, though rendering the page confirms it.
