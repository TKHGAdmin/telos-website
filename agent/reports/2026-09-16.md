## Findings

### [P1] BUG-20260916-01 — Product detail info panel drops below the image whenever thumbnails render

- **File(s):** `product.html:765-780`, `product.html:100-116`, `js/shop.js:165-177`
- **Severity:** P1
- **Category:** functional
- **Summary:** The thumbnail row was inserted as a direct child of the 2-column CSS grid, so it consumes the grid cell that the product info panel is supposed to occupy, pushing title / price / Add-to-Cart below the hero image on desktop.
- **Repro:**
  1. In `product.html:100-108`, the container is declared as `.product-detail.loaded { display: grid; grid-template-columns: 1fr 1fr; }`.
  2. Its three direct children in DOM order (`product.html:765-780`) are: `#productImage`, `#productThumbs`, then `.product-detail-info`.
  3. With default `grid-auto-flow: row`, the browser places them left-to-right, top-to-bottom: cell (1,1)=image, cell (1,2)=thumbs, cell (2,1)=info. Cell (2,2) is empty.
  4. `js/shop.js:165-174` populates `#productThumbs` whenever `allImages.length > 1`. On any product with ≥ 2 images (which the new gallery is designed for), the thumb strip renders in the right column and the info panel is pushed to the row below the hero image.
  5. Even for single-image products, `#productThumbs` is still a grid item — it consumes cell (1,2) with zero height but nonzero column allocation, so `.product-detail-info` still lands in row 2, col 1 instead of row 1, col 2.
  6. No `grid-column`, `grid-row`, or `grid-area` override exists for `.product-detail-thumbs` (confirmed by grep across the repo — only the definition at `product.html:120` and the DOM node at `product.html:767`).
  7. On mobile the media query at `product.html:110-115` collapses to one column, so this bug is desktop-only (viewport > 768px).
- **Impact:** Every desktop visitor to `/product?p=<handle>` sees the product name, price, and Add-to-Cart button below the fold on typical laptops (16:9 image is ~560px tall), suppressing conversion. This is the primary purchase surface for the new Shop, so it directly affects revenue on any product with more than one image, and to a lesser extent on single-image products too.
- **Proposed fix:** Nest the thumbnails inside a wrapper alongside the image (so the grid still has two children), or set `grid-column: 1;` on `.product-detail-thumbs` so it stacks under the image rather than displacing the info panel. Simplest structural fix: wrap `<div id="productImage">` and `<div id="productThumbs">` in a single `<div class="product-detail-media">`, and leave `.product-detail-info` as the second grid child.

## Notes

- The `escapeHtml` helper in `js/shop.js:509` uses `document.createTextNode` and therefore only escapes `<`, `>`, and `&` — not `"` or `'`. It is currently used inside HTML attributes (e.g. `alt="${escapeHtml(product.title)}"` and inline `onclick="addToCart(this, '${variant.id}')"`), which would break the DOM if any Shopify field ever contained a `"` or `'`. Not reported this run because store owner input is the only source and no such value exists today; recorded in `learnings.md` for the next Security day.
- The Shopify Storefront access token in `js/shop.js:15` is by design a public token (Shopify's Storefront API model). Not a leaked secret; logged in `learnings.md` to prevent re-flagging.
