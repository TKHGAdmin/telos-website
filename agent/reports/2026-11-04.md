## Findings

### Finding 1 - Quiz lead-capture gate bypassable; leads lost

- **ID**: BUG-2026-11-04-01
- **Severity**: P1
- **Category**: functional
- **File(s)**: index.html:580, pricing.html:594, js/quiz.js:220-275
- **Status**: new

**What's wrong**
The quiz "See Your Score" button is declared `type="button"`, not `type="submit"`, so the form's native `required` validation on `name` and `email` never fires. `js/quiz.js`'s click handler reads the input values directly without any client-side validation and immediately shows the results pane. A user can click through with every field blank, see their score, and — on pricing.html — proceed to the pricing view, with no lead data captured. The POST to `/api/submit-quiz` goes out, gets rejected with 400 ("Name and email required"), and the rejection is swallowed by `.catch(function(){})` so the user never sees any error either.

**Reproduce**
1. Open https://www.telosathleticclub.com/pricing in a private window (so `localStorage.telosQuizCompleted` is unset).
2. Complete the 8 quiz questions by clicking any option on each (auto-advance).
3. On the "Your Score Is Ready" screen — which displays `PRICING UNLOCKS AFTER THIS STEP` — leave Name, Email, and Phone completely empty.
4. Click **See Your Score**.
5. Expected: the browser blocks submit and focuses the first empty required field.
6. Actual: results pane renders, the "View Pricing" button appears, `localStorage.telosQuizCompleted` is set to `'true'`, and pricing unlocks. The `/api/submit-quiz` call returns 400 silently; no lead row is written to Upstash.

Root cause trace:
- `index.html:580` and `pricing.html:594`: `<button type="button" class="btn btn-primary quiz-see-score-btn">...`
- `js/quiz.js:225-275`: `submitBtn.addEventListener('click', ...)` reads `nameInput.value` / `emailInput.value` with no non-empty check, writes `localStorage.telosQuizCompleted = 'true'` (line 247), fires the fetch with `.catch(function(){})` (line 269), then unconditionally shows results.
- `api/submit-quiz.js:18-20`: `if (!email || !name) return res.status(400)...` confirms the backend contract treats both fields as required, matching the `required` attributes on the inputs — the frontend just doesn't enforce it.

**Impact**
Every quiz completion on pricing.html that skips the form unlocks pricing without delivering a lead, defeating the business-critical lead-capture gate on the only paid-conversion page. Same on index.html with less severe consequences (score is shown, lead is lost). Thomas's dashboard under-counts quiz-driven leads.

**Suggested fix**
Either change `type="button"` to `type="submit"` and let the native `required` + `type="email"` validation fire (plus wire the handler to the form's `submit` event with `preventDefault`), or add an explicit `if (!quiz.userName || !quiz.userEmail || !/.+@.+\..+/.test(quiz.userEmail)) { show inline error; return; }` block at the top of the quiz.js click handler before writing `telosQuizCompleted`. Phone can stay optional either way.
